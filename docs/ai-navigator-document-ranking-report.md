# AI Navigator Document Ranking Report

Дата: 2026-06-24

## Проблема

Для запроса «уволили без причины» ИИ-навигатор правильно определял ситуацию как
трудовой спор (корректный `primaryAction` и `summary`), но в секции **Документы**
показывал нерелевантный документ из семейного права — **«Исковое заявление о
расторжении брака»**.

Корневая причина — две связанные проблемы в `src/lib/site-search.ts`:

1. **Domain guard не применялся к документам.** Домен результата вычислялся
   `getResultDomain()` только по `href`. У всех документов `href` имеет вид
   `/documents/<slug>/` и не содержит категории, поэтому документы всегда получали
   домен `"other"`. Из-за этого `isConflictingResult()` (который отсекает семейные
   материалы из трудовых/потребительских/жилищных/наследственных запросов) никогда
   не срабатывал для документов, а `domainBoost()` не усиливал релевантные документы.

2. **Ложное совпадение по стоп-слову.** В `scoreResult()` word-bag использовал все
   слова длиной ≥ 3, включая служебное «без». Текст документа о разводе содержит
   «без личного контакта», поэтому запрос «уволили **без** причины» давал документу
   ненулевой score исключительно из-за предлога.

## Что исправлено

Все изменения — в `src/lib/site-search.ts`, публичные контракты не затронуты.

1. **Доменная классификация документов** (`documentDomainsByHref`): домены документа
   выводятся из его `relatedProblemSlugs` (проблема → категория → домен через
   `categorySlugToDomain` / `problemDomainBySlug`) и подкрепляются текстовыми
   семейными маркерами (`familyDocMarkers`: развод, брак, алимент, супруг, усыновлен,
   родительск, раздел имущества, место жительства ребенка). Покрывает и страницу
   документа, и его генератор.
2. **Set-семантика домена** (`getResultDomains`): результат может принадлежать
   нескольким доменам. Документ исключается из конфликтующего запроса, только если он
   **не разделяет** ни одного домена с запросом — это предотвращает ложное исключение
   мультидоменных документов.
3. **Domain guard распространён на документы**: `isConflictingResult()` теперь
   использует `getResultDomains()`. Правило: запросы доменов
   employment / housing / consumer / inheritance / documents не показывают семейные
   материалы (включая документы), если нет совпадения домена. Исключение для точного
   совпадения названия документа (сильный прямой сигнал) сохранено.
4. **Domain boost для документов**: релевантные по домену документы получают `+180`.
5. **Стоп-слова** (`searchStopwords`): служебные слова (без, для, или, что, при …)
   исключены из word-bag в `scoreResult()`. Значимые короткие слова («иск», «суд»,
   «долг») сохранены. Подстрочные совпадения (точное/префикс/вхождение) не затронуты.

Принцип «лучше пустой `documents`, чем неверный документ» соблюдён: если релевантного
документа нет — секция пустая.

## Remaining issues

- **«алименты» → 0 документов** (и до, и после правок). Документ «Заявление о
  взыскании алиментов» не всплывает: его `relatedProblemSlugs` хранятся латиницей
  (`alimenty`), а кириллическое «алименты» в haystack документа отсутствует. Это
  предсуществующий пробел токенизации, не регрессия данной задачи. Лечится
  обогащением keyword'ов документов (вне scope: затрагивает ранжирование, а не
  domain-guard).
- **«уволили без причины» → пустой `documents`** (а не трудовой документ). Это
  допустимо по ТЗ («documents либо трудовые, либо пустые»; «лучше пустой, чем
  неверный»). Чтобы показать «Заявление о восстановлении на работе», нужно связать
  документы с primary-ситуацией через `relatedProblemSlugs` (шаг 5 ТЗ) — отдельное
  улучшение релевантности, не входит в минимальный фикс.

## Recommendation

1. Закрыть текущую задачу: критический баг (семейный документ в трудовом запросе)
   устранён, регрессий нет, типы/линт/тесты зелёные.
2. Отдельной задачей — обогатить keyword'ы документов кириллическими формами
   (`алименты`, `развод`, …) и добавить связь документов с primary-ситуацией по
   `relatedProblemSlugs`, чтобы трудовые/семейные/потребительские документы активнее
   и точнее всплывали по соответствующим запросам.
3. Деплой — по отдельной команде.
