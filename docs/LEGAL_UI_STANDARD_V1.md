# Единая структура интерфейса юридических маршрутов

## Стандарт

Каждая ситуация из 43 зарегистрированных маршрутов доступна по существующему URL и показывает одинаковую верхнюю навигацию **Ситуация → Выбор пути → Анкета → Результат → Проверка**. Навигация служит подсказкой о прогрессе, а не юридической оценкой. Этапы без прямого безопасного адреса не выглядят интерактивными.

Общий макет на всех страницах ситуаций и документов:
- `LegalRouteJourney` в layout проблем и документов;
- согласованные типографика, выделение фокуса для клавиатуры, размер полей на телефоне и цвет активных элементов;
- `DocumentResultSummary` показывает отсутствие подтверждённой готовности к подаче и предлагает **необязательное** сохранение;
- `DocumentVersionHistory` в активной вкладке; постоянное хранение отдельно, через явное действие пользователя.

В трудовых маршрутах и пяти дополнительных семейных используется один `LegalFormField`: явные `label`, `required`, `aria-invalid`, `aria-describedby`, ошибки, подсказки и тип ввода. Существующие индивидуальные валидаторы не заменяются общими.

## Что этот этап не подтверждает

24 ранее самостоятельных семейных маршрута ещё используют собственные реализации анкет; общий внешний маршрут и единый контракт документа не означают побайтово одинаковую форму или полный E2E каждого юридического исключения. Ранее введённые сведения не переносятся между всеми разными формами автоматически. Для утверждения полной унификации требуются точечные рефакторинги каждого генератора без изменения исходных юридических решений.

Техническая проверка интерфейса: `tests/e2e/legal-journey-43.spec.ts`. Каждая страница ситуации проверяется на наличие одного заголовка H1 и пятиэтапной навигации. Это не заменяет аудит доступности WCAG и юридическую экспертизу.
