# AI Navigator Clarifying Questions Report

Дата: 2026-06-24

## Что изменено

Цель: уточняющие вопросы ИИ-навигатора стали целевыми под тему запроса, а не
шаблонными. Публичный контракт `/api/ai-navigator/` не менялся; `/api/search-suggestions/`
не трогался. LLM по-прежнему не может менять ссылки/sections/documents/primaryAction/
riskLevel/urgency/confidence — роут мержит только `summary`, `steps`, `clarifyingQuestions`.

Файлы:

- `src/app/api/ai-navigator/route.ts` — `buildClarifyingQuestions` теперь доменный:
  домен определяется по категории primary-маршрута (href) или по маркерам запроса
  (employment / debt / consumer / family / housing / inheritance / documents). Для
  каждого домена — предметный набор из 4 вопросов. Общий набор (`GENERIC_CLARIFICATIONS`)
  — только если домен не определён.
- `src/lib/ai/navigator-llm.ts`:
  - system prompt переписан под формулировку точных уточняющих вопросов + few-shot
    примеры (Работа / Долги / Покупки);
  - compact context дополнен полем `primary` (title/description/categoryLabel/href
    найденного маршрута); keywords/headers/cookies/IP по-прежнему не передаются;
  - user prompt структурирован: запрос / основной маршрут / материалы сайта / ответы
    пользователя / форма JSON;
  - валидация вопросов усилена: максимум 220 символов, дедупликация, отбрасывание
    вопросов, почти совпадающих с уже отвеченными, и приоритет предметных вопросов
    над общими (общие принимаются только если предметных < 2). 2–4 вопроса до
    уточнения, 0–4 после. При плохом ответе LLM → `{}` → роут оставляет доменный
    fallback.

## Fallback questions (LLM выключена)

| Query | Questions | Status |
| ----- | --------- | ------ |
| уволили без причины | Когда вас уволили…; Какое основание в приказе/трудовой…; Заявление по собственному или соглашение сторон…; Получили расчёт и копию приказа… | PASS (employment) |
| приставы списали деньги | Номер исполнительного производства…; Когда узнали о списании/аресте…; С какого счёта (зарплата/пенсия/пособие/карта)…; Получали судебный приказ/решение/постановление… | PASS (debt) |
| магазин отказал в гарантии | Когда купили товар/заказали услугу…; Есть чек/договор/переписка…; Что ответил продавец…; Подавали письменную претензию… | PASS (consumer) |
| умер родственник что делать | Когда умер наследодатель…; Обращались к нотариусу…; Завещание или по закону…; Пропущен ли 6-месячный срок… | PASS (inheritance) |
| потерял паспорт | Какой документ восстановить/оформить…; Когда и где выдан/утрачен…; Есть копия/фото/номер…; Для чего нужен (суд/сделка/госуслуга/работа)… | PASS (documents) |

Общих вопросов вида «Когда произошла ситуация?» в fallback больше нет.

## LLM questions (включена)

Реального провайдера в окружении нет, поэтому путь с включённой LLM проверен через
локальный mock-провайдер (полный цикл: prompt → fetch → parse → валидация).

| Сценарий | Что вернул mock | Результат после валидации | Status |
| -------- | --------------- | ------------------------- | ------ |
| Норма + шум | 2 предметных + общий «Когда произошла ситуация?» + дубль + вопрос >220 симв. | 2 предметных + 1 обрезанный до 220; общий и дубль отброшены | PASS |
| После уточнения | «Когда вас уволили?» (уже отвечён) + предметный про приказ | остался только предметный (отвечённый отброшен) | PASS |
| Битый JSON | `not a json` | `{}` → роут оставляет доменный fallback | PASS |

## Safety checks

- links unchanged — да (роут мержит только summary/steps/clarifyingQuestions; href не из LLM).
- sections unchanged — да (sections берутся из детерминированного ответа, LLM их не возвращает).
- documents unchanged — да (как и sections).
- primaryAction / riskLevel / urgency / confidence unchanged — да.
- fallback works — да (LLM off, невалидный ответ, мало предметных вопросов → доменный шаблон).

## Remaining issues

- Качество вопросов с реальной LLM зависит от провайдера и модели; проверено только на
  mock. Перед публичным включением LLM желательно прогнать 8 запросов из ТЗ на реальном
  провайдере и сверить формулировки.
- Доменные маркеры запроса эвристические; редкие формулировки без primary-маршрута могут
  попасть в общий набор (это безопасный, но менее предметный fallback).
