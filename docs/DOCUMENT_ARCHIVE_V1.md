# Приватный архив юридических документов V1

## Область действия

Пользователь с ролью `USER` может **по явному нажатию** сохранить результат `DOCUMENT_RESULT_V1` в личный кабинет `/account/documents/`. Отсутствует автоматическое копирование ответов в localStorage, публичные URL, аналитику и логи.

Каждая версия неизменяема, имеет отдельный `versionId` и принадлежит конкретному `User.id`. Архив позволяет открыть сохранённый текст, экспортировать **новую архивную PDF-копию** и окончательно удалить версию. Архивная PDF-копия не гарантирует исходную вёрстку специализированного генератора или официального бланка. Сохранение **не** подтверждает юридическую корректность.

## Безопасность

- Текст, заголовок, персональные факты и метаданные результата внутри `encryptedPayload` шифруются AES-256-GCM с новым случайным nonce при каждом шифровании.
- Дополнительные аутентифицируемые данные привязывают шифртекст к `userId` и `versionId` и предотвращают подмену строками другой учётной записи.
- Необходим `DOCUMENT_STORAGE_KEY`: 32 случайных байта, строго base64. Генерация: `openssl rand -base64 32`.
- Ключ находится **только** в серверной конфигурации, не в Git и не в переменных `NEXT_PUBLIC_*`. При отсутствии ключа сохранение блокируется, без ослабленного режима.
- Строки БД содержат `versionId`, `userId`, `encryptedPayload` и время; отсутствие отдельного открытого текстового названия ограничивает утечки метаданных.
- Все операции требуют проверки аутентифицированного пользователя с ролью `USER`. Чтение и удаление фильтруются по `userId`. Чужая версия не различима с несуществующей — HTTP 404.
- Для модифицирующих запросов применена общая проверка происхождения запроса, ограничения размера и частоты. GET и ответы используют `Cache-Control: private, no-store`.
- Количество версий ограничено 100 на пользователя. Удаление каскадное при удалении учётной записи.

## Локальная проверка

1. Подключить локальную PostgreSQL через `DATABASE_URL` и заполнить `DOCUMENT_STORAGE_KEY` в скрытом `.env.local`.
2. `npm ci`, затем `npm run prisma:generate && npm run prisma:deploy`.
3. `npm run test:archive-crypto`, `npm run typecheck`, `npm run build`, затем `npm run dev`.
4. Авторизоваться под ролью `USER`, сформировать документ и нажать «Сохранить в мои документы».
5. Обновить страницу, открыть версию в кабинете, скачать архивную копию PDF, затем удалить версию. С другой учётной записью доступ должен возвращать 404.
6. Контрольный E2E `tests/e2e/saved-document-cabinet.spec.ts` использует отдельную тестовую БД и **временные** ключи CI.

## Границы и выпуск

- Персональные данные сохраняются **только по согласию через действие пользователя**. До production требуется проверить политику хранения и удаления, восстановление из резервной копии, полномочия персонала и работу с запросами субъекта данных.
- Потеря ключа делает существующие версии нечитаемыми. Простая замена ключа невозможна: до ротации реализовать контролируемое перешифрование с журналом и резервным восстановлением.
- В данный момент не сохраняется байтово-точный исходный PDF специализированного генератора, а сохраняется нормализованный текст и поля `DocumentResult`; архивный экспорт является **новой** PDF-копией.
- Ни генерация, ни сохранение, ни сквозные технические тесты не заменяют экспертизу юриста. `filingReady=false`.
- Реальные персональные документы запрещено загружать в CI или публичные логи. Проверки используют синтетические данные.

## API

- `GET /api/account/documents/` — только метаданные версий текущего владельца.
- `POST /api/account/documents/` — создать новую неизменяемую версию из верифицированной схемы и зарегистрированного маршрута.
- `GET /api/account/documents/{versionId}/` — расшифровать только версию владельца.
- `DELETE /api/account/documents/{versionId}/` — удалить только версию владельца.

При конфликте версии — HTTP 409; без сессии — HTTP 401; чужая или несуществующая версия — HTTP 404.
